# Cue

Personal task, habit and routine manager that lives behind a Claude connector. The repo and Vercel project are still called `nick-tasks`. Both `https://nick-cue.vercel.app` and `https://nick-tasks.vercel.app` serve it (and the `-nickcoronas-projects` URL); sign-in cookies are per domain.

- `api/mcp.js`: MCP server (Streamable HTTP, stateless JSON). Auth is a secret path segment (`/mcp/<APP_KEY>`), or on `/mcp` a bearer token: the APP_KEY itself or an OAuth access token.
- `api/oauth.js`, `lib/oauth.js`: stateless OAuth 2.1 (discovery, dynamic client registration, PKCE) for clients that need it, e.g. Meta Muse. The consent page asks for the APP_KEY, or just Allow on a signed-in device. Tokens are HMAC-signed from APP_KEY, so rotating it revokes them.
- `api/web.js`: web view. `/app/<APP_KEY>` signs a device in (1-year cookie) and redirects; after that `/` is the full queue and `/w` the compact widget view. Also serves the PWA manifest and service worker.
- `lib/tools.js`: tool definitions, server instructions, handlers.
- `lib/logic.js`: ranking (Apparent Tardiness Cost with Smith's-rule baseline), planning-fallacy correction, habit and routine status. Contexts map to four places (`placeOf`: computer, phone, home, out); for 45 minutes after a check-off, up to two tasks in the same place scoring at least 60% of the top one move to the front. Today's list is grouped by place.
- `lib/ui.js`: the queue UI, served both as an MCP App (`ui://nick-tasks/queue.html`, rendered inline in Claude by `show_queue`) and as the web view.
- `lib/views.js`: the plan-my-day (`show_plan`) and weekly-review triage (`show_review`) cards, MCP Apps only. The plan card sends the approved plan back to the chat for Claude to put on the calendar; the triage card applies decisions itself.
- Daily sweep (first read each local day, in `lib/tools.js`): drops tasks past `expires`, counts strikes for tasks left untouched in the top 10, parks stale wishes, and turns overdue waits into `who=claude` follow-ups. Routine ticks are keyed by step id.
- `lib/calendar.js`: busy time from Google Calendar's secret iCal address(es) in env `CALENDAR_ICS_URL` (comma-separated). Only events inside `personal_hours` count, minus Cue's own plan/routine events; that day's task capacity drops by the busy minutes. `busyUntil` also tells the push consumer whether he's in an event right now: a buzzing Now ping or idle nudge then waits until a minute after it ends.
- `lib/push.js`, `api/push.js`, `api/push-fire.js`: phone notifications (web push). Each ping is a Vercel Queue message delayed to its exact time; on delivery it re-checks the ping still applies before pushing. The installed app's "Turn on notifications" button subscribes the device. With `push.now` on (default), routine/habit pings collapse into one Now notification (tag `cue-now`) that shows the single next thing (`nowItem`: running routine's next core step, then due habits, then the top task); its Done and Not now buttons hit `/push?action=check|now_skip`, which answer with the next item for the service worker to show in place. It buzzes at wake and each routine/habit time, and quietly refreshes after check-offs in the app. The title line is short context ("Morning routine · 4/5", "Move · 2/3 today") since Chrome shares it with the site name; the action leads the full-width body. The large icon is a progress ring (`/ring.png?d=&n=`, `lib/ring.js`): core steps, habits due today, today's 3 tasks, or the focus block's minutes. Tasks add the first line of their note (routine steps don't: they repeat daily). A task over 10 min gets Start 25 min (`/push?action=now_focus`, a focus block) in place of Done; while a block runs the notification holds it, and Done stops it as done. The queue shows Today's 3 tasks, the rest behind a tap. Not now on a task also opens Cue (`/?stuck=<id>`) asking what's in the way: don't know how (adds a `who=claude` "Prep:" task), too big (he names a first step, `shrink_task`), or not feeling it (a 5-minute focus start). Idle nudge (`push.idle`): in personal hours, an hour with nothing checked off, focused on or logged re-buzzes Now as "Stand up first" (at most twice in a row); each active tool call in `callTool` queues the next check an hour out, and `lastActive` decides on delivery. Env: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
- `lib/lift.js`, `lib/liftui.js`: Cue Lift at `/lift`. Programs attached to lift habits, sessions with every set, double-progression targets, PRs, weekly hard sets per muscle. Finishing a session checks off the habit; rest timers ping via push.
- `lib/screen.js`: shared core for purpose-built screens (page shell, base styles, server calls, header, wake lock). `lib/focus.js`, `lib/focusui.js`: Cue Focus at `/focus`, timed work blocks on a task; done blocks check the task off with real minutes (estimate correction) and count toward goal minimums as they happen.
- `lib/mood.js`, `lib/moodui.js`: Cue Mood at `/mood`, behavioral activation. Entries are a 0-10 mood plus an activity and a reusable activity family (inherited from a linked task, habit or routine). Each entry can also rate mastery (sense of accomplishment). Insights compare each family's mood and mastery with the window baselines (lift), grey out families under 3 entries, separate builders (mood dip, mastery gain) from drains, and show mood by 2-hour block. Plans (`plan_activity`) schedule an activity at a time with a predicted mood, ping when due, and rating them gives predicted vs actual and planned-vs-done follow-through. Logging lives on the queue: a "Log mood" bar for anything (also opened by check-in pings), with today's unrated check-offs as one-tap picks; an optional "mood now?" picker after a task with a predicted mood, or after a habit or whole routine at most once an hour (accomplishment is only asked after tasks); and from 8pm or wind-down a "Rate today" card listing what was done today without a rating (`unrated_today` in the queue); cards whose activity reliably lifts mood (28 days) or builds mastery get a tag, and a task's `predicted_mood` is compared with the rating after its check-off. The queue offers the picker, and `push.mood` turns on 2-hourly check-in pings from `settings.wake` to an hour before bed. Tests: `npm test`.
- `lib/cook.js`, `lib/cookui.js`: Cook mode at `/cook`. Recipes (ingredients with store, steps with timers, protein per serving), a prep check that sends missing ingredients to the shopping list, big-text steps with concurrent timers that ping via push, and a rating and note shown next time. A routine step with `recipe_id` gets a Cook button and is ticked when the cook finishes.
- `lib/build.js`, `lib/buildui.js`: Build at `/build`, project backlogs instead of GitHub issues. Items go inbox → ready (has done-when checks) → building → shipped, with commit links. Capturing the same friction again adds a hit, and items rank by recent hits, then size. Each project's top item joins the queue as `b_<id>` (checking it off ships it). Copy brief gives a paste-ready spec for a Claude Code session.
- `lib/today.js`: today's list. Locked once a day (sweep, or the first read) from the top of the ranking, filling a time budget equal to the last 7 days' average finished minutes x1.1 (min 15, max capacity), 1 to 5 tasks. A low day (said via `set_day`, the latest mood today at 4/10 or below, or nothing done by 11:00) shrinks it to the quickest one. The queue returns `today` and `today_tasks`; the app shows them first with a Low day toggle and "Keep going" into the ranked rest as bonus; the Now notification serves the list, lets a hard deadline due today break in, then offers bonus.
- `lib/metrics.js`: how Cue is working, week over week, for the weekly review (`review` returns `how_cue_is_working`): tasks finished, days with anything done, days today's list was finished (from `meta.days_log`, kept when a new day's list is locked), morning routine core completion, median minutes from wake to the first thing done, and Now notification Done vs Not now taps (`meta.push_actions`).
- `lib/steps.js`: what routine steps are made of. Steps can run `from`/`until` a date or `until_task` (a task closing sets the date, in the sweep and on check-off), carry `temp_notes` that lapse the same way, use a product (`save_product`: actives, storage, opened + `pao_months` or `expires`, `uses`; `products` reports use-by, uses left from step ticks, and active-ingredient clashes within a routine), and have a 0-10 `metric` scored with `score_step`. A metric's `trial` alternates on/off blocks (off days: skip the step, still score; first `washout_days` of each block left out) and `step_trial` compares the arms. In the app a metric step asks its score after Done; on an off day it shows Score instead; its notification opens the picker.
- `lib/store.js`: one JSON document in a private Vercel Blob, ETag-guarded writes, daily backups.

Deployed on Vercel (project `nick-tasks`). Env: `APP_KEY`, optional `CALENDAR_ICS_URL`, plus a connected Blob store (`BLOB_STORE_ID`, OIDC).

## Setup notes

- Connector: claude.ai → Settings → Connectors → Add custom connector, URL `https://nick-tasks-nickcoronas-projects.vercel.app/mcp/<APP_KEY>`. After changing tool metadata (e.g. the MCP App link), reconnect so Claude reloads the tool list.
- Meta Muse: Settings → Connectors → Add custom connector, URL `https://nick-tasks.vercel.app/mcp`, then Allow on the sign-in page. If Muse instead builds the connector in chat, give it that URL with auth = bearer token and enter the APP_KEY in its secure credential prompt, not the chat.
- Deploys: the Vercel project is linked to this repo, so pushes to `main` deploy to production and PRs get preview deployments.
- Pings: timed routines and habits are recurring Google Calendar events; a scheduled Claude task (7:47am and 4:47pm Toronto) reads `get_queue` and `review` and pushes only when something needs attention.
- Phone: open the long `/app/<APP_KEY>` link once in Chrome, then menu → Install app (or Add to Home screen) for a full-screen app icon. For a live home-screen widget, point a web-widget app at `https://nick-tasks.vercel.app/w`.
